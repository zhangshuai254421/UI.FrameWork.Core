## 1. 数据库迁移（EF Core Migration）

框架中有两个 SQLite `DbContext`，分别位于不同项目：

| DbContext | 所属项目 | 数据库文件 |
|-----------|----------|------------|
| `Recipe.Domain.DataContext` | `Recipe.Domain` | `AppGlobals.RecipeDbFliePath` |
| `Log.Domain.DataContext` | `Log.Domain` | `AppGlobals.LogDFliePath` |

迁移命令在 **程序包管理器控制台（Package Manager Console，PMC）** 中执行。

### 1.1 生成迁移（Add-Migration）

通用格式：

```
Add-Migration -Name <迁移名称> -StartupProject <启动项目> -Project <DbContext 所在项目>
```

示例（为 Recipe.Domain 生成名为 `Update01` 的迁移）：

```
Add-Migration -Update01 -StartupProject SemiAppliaction -Project Recipe.Domain
```

### 1.2 更新数据库（Update-Database）

通用格式：

```
Update-Database -StartupProject <启动项目> -Project <DbContext 所在项目>
```

示例：

```
Update-Database -StartupProject SemiAppliaction -Project Recipe.Domain
```

### 1.3 参数说明

| 参数 | 含义 | 说明 |
|------|------|------|
| `-Name` | 迁移名称 | 仅 `Add-Migration` 使用，建议使用有意义的名称（如 `AddRecipeTable`） |
| `-StartupProject` | 启动项目 | 固定为 `SemiAppliaction`（UI.FrameWork 项目，启动时执行 `EnsureCreated`） |
| `-Project` | 目标项目 | `DbContext` 所在的项目，决定迁移文件生成到哪个项目 |

### 1.4 其他常用命令

| 命令 | 作用 |
|------|------|
| `Remove-Migration -Project Recipe.Domain` | 删除最近一次未应用的迁移 |
| `Script-Migration -Project Recipe.Domain` | 生成 SQL 脚本（不直接执行） |
| `Get-Migrations -Project Recipe.Domain` | 查看已生成的迁移列表 |

### 1.5 注意事项

1. 在 PMC 顶部的"默认项目"下拉框中选中 `SemiAppliaction`，可省略 `-StartupProject` 参数。
2. 为 `Log.Domain` 迁移时，将 `-Project` 改为 `Log.Domain`，其余参数不变：
   ```
   Add-Migration -Name <迁移名称> -StartupProject SemiAppliaction -Project Log.Domain
   ```
3. 项目已通过 `IDesignTimeDbContextFactory<DataContext>`（见 `Recipe.Domain/DataContext.cs`）提供设计时上下文，无需 `-Context` 参数。
4. 多目标框架（`net8.0-windows;net10.0-windows`）下若 PMC 报错，先确保解决方案已成功编译一次。
5. 修改实体后需重新执行 `Add-Migration` 生成新的迁移，再执行 `Update-Database` 应用。
