# 去马赛克是适配器职责：UI 链路只见规范像素格式

Status: accepted

核心原则一句话：彩色相机的拜耳→RGB 插值在适配器内完成，适配器产出的相机帧永远是规范格式（Mono / RGB / BGR），映射器与控件永不接触拜耳原料。

## 规则

1. **适配器翻译到底**：厂商 SDK 给拜耳原料（如 BayerRG8）时，适配器先插值成 RGB，再以 `PixelFormat.RGB8` 包装 `CameraData` 推进通道。这与其术语表定义一致——适配器就是把厂商私有驱动翻译成统一接口的那一层。
2. **拜耳枚举值是规范表示，不是出帧许可**：`PixelFormat` 里的 Bayer 值保留，但适配器不得把拜耳格式的相机帧推给 UI 消费者。
3. **违约信号**：宿主侧 `CameraFrameMapper.ToImageFrame`（UI.FrameWork.Core/Imaging）收到拜耳/未定义格式即丢弃并告警（每格式限频一次）——出现该日志即适配器违反本约定。
4. **现有 Mono 适配器无感**；将来彩色适配器实现时执行本规则。

## Considered Options

- **宿主侧去马赛克**（映射器做）：弃用——每个 UI 消费者都得处理一遍；插值算法/库被拉进宿主层。
- **控件侧去马赛克**：弃用——拜耳是设备侧概念，控件做它就破坏了控件零设备依赖（ADR-0004）。
- **适配器职责（选定）**：单一出口，所有 UI 消费者自动受益；插值方式（查表、SDK 硬件加速）留在驱动层，UI 无感。

## Consequences

- 半年后写新适配器的人看到枚举里有 Bayer 也不能透传——这是故意的，枚举注释里已留指引。
- 丢帧告警日志是发现违约的哨兵：见 `相机帧格式 ... 不受支持` 即适配器没做去马赛克。
