# 事件落库改写后队列：履历完整性与冻屏之间选不冻屏

Status: accepted（翻案 ADR-0009 规则 5 的「订阅即落库」时序语义——落库时序改异步，append-only 铁律与存储接缝不动）

核心原则一句话：**订阅即入队，后台单写者冲账**——引擎产事件的线程只付入队成本，库再慢冻的是后台写者、不是事实流与 UI；`IEventStore` 的 append-only 接缝与「每一拍全量进本子」的目标不变，翻案的只是「落库同步于产事件」这一条时序语义（#31）。

## 背景

#29 把演示页泵线挪去后台修的是症状：`EventHistory` 仍把 `store.Append` 直订在引擎 `EventRaised` 上，而引擎全程持 `_gate` 锁内播报（`Raise`）。库文件被外部进程独占（备份/杀毒）时，Append 的 SQLite busy 等待（命令超时默认 30 秒）在引擎关键区里拖住所有 UI 线程调用（确认/搁置/解除/活跃快照全过 `_gate`）——#29 要消灭的冻结从它没拆的锁绕了回来。同场景下列表 VM 的详情重取（`SelectedRow` setter 直连 `_store.Find`）也把 UI 线程按在同一把文件锁上。#31 评审定位：修的是症状不是病根（落库在引擎关键区里同步做）。

## 翻案内容（对 ADR-0009 规则 5）

1. **「订阅即落库」→「订阅即入队，后台冲账」**：`EventHistory` 接线改写后队列——构造时把馈送的事件流接进有界内存通道（容量默认一万拍），后台唯一写者按进队次序逐条 `Append`，一条落定才取下一条（本子次序即履历次序，搁置单回放 #16 靠它）。引擎（`AlarmEngine`）一行不动——判定权与存储的隔离（规则 5 的「引擎不直连数据库」）反而更干净：busy 等待从此物理上进不了引擎关键区。
2. **新增一条已接受的取舍——崩溃窗口**：进程在冲账前崩溃，队列里的尾部事件丢失。GB/T 41261 履历完整性 vs 操作员冻屏之间拍板选不冻屏：冻住的 UI 让操作员错过的是正在响的报警（安全侧受损），丢的尾部事件只是事后体检（KPI）少几行。库正常时事件秒级落定，窗口只在崩溃瞬间与库持续不可用两处。
3. **库不可用时的降级序列（有界、可解释）**：单拍失败后台按拍重试（默认 1 秒）到成功为止，顺序不跳位；库持续进不去则队列封顶，**满了丢新保旧**（`DropWrite`）——最先发生的证据优先存活，履历头上不缺页；`Dispose` 收工冲账（停进水 → 关闸 → 清完存量），但库持续进不去时在途重试让位收工，不拖着宿主关屏等 busy 窗口。
4. **读侧同场解耦（#31 的另一半）**：UI 线程不再直碰库——列表 VM 的详情档案改后台预取（取档接缝注入，默认 `Task.Run`；换行对暗号防慢档闪旧账；取档炸了停在取档处不炸上 UI）。引擎 `_gate` 内从此没有任何库 I/O。

## 规则

1. **接缝形状不变**：`IEventStore` 仍只有 `Append` 与 `Query`，append-only 铁律照旧（ADR-0010 规则 1 原样存活）；写后队列是 `EventHistory` 的实现细节，宿主无感。
2. **引擎关键区内零库 I/O**：`AlarmEngine` 的锁内不许出现任何存储调用——这是本 ADR 的可执行判据，评审按此验收。
3. **顺序是履历的一部分**：后台写者单线程逐条冲账，进队次序即落库次序；任何并行写方案（多写者、乱序批量）都破坏「书写次序即履历次序」，弃用。
4. **降级必须说出口**：丢新保旧、收工让位都是有损路径，`EventHistory` 的文档注释如实记载语义；v2 的 KpiService/监控面如需「丢账计数」，走独立挂钩，不回改接缝。

## Considered Options

- **B 短超时同步 + 超时转后台**：弃用——常态下每拍事件多付一次线程切换，只为买「多数情况即时落盘」；超时窗内照样丢，语义反而含混（到底同不同步？）。写后队列常态成本更低、语义一条到底。
- **C 只读侧解耦（最小修）**：弃用——只拆了回页选行那半条冻屏路，点「确认」那条（写侧，标题病根）原样保留。
- **A 写后队列 + 读侧预取（选定）**：引擎关键区只付入队成本，病根全清；代价（崩溃窗口）显式立 ADR 接受。

## Consequences

- `EventHistory` 从 15 行一行接线长成有生命周期的小类（通道 + 后台写者 + `Dispose` 冲账），随引擎存亡的接线语义不变；`AlarmDemoRig` 暴露 `History` 供测试冲账与宿主收口。
- 哲学文档 §8.1 表述随本 ADR 同步修订为 v1.2（「订阅即落库」→「订阅即入队，后台冲账」）；append-only 与 90 天保留期两条【强制】不动。
- 验收钉子在测试里：`库被锁住_事件流不等落库`（BlockedEventStore 卡闸，事件流照常走）、`队列满_丢新保旧`、`落库失败_重试到成功`、`收工让位`；读侧 `详情_默认后台取档_不占选中线程`。
- 演示页重启回放（#16 搁置单）读的是库，入队与冲账的窗口对它不可见——重启前 `Dispose` 冲账即可，演示装置随宿主存亡天然满足。
