# 主界面导航最深 3 级：第 4 级是红线，超深需求一律扁平化

Status: accepted

核心原则一句话：MainRegion 导航栈最深 3 级（主页 = 第 1 级），出现第 4 级需求时，先换成页内交互手段，而不是继续跳页。

依据：工业 HMI 标准 ISA-101 将显示层级定为 3 层（总览 / 区域详情 / 诊断维护），设备上位机适用此标准；每深一级，操作员对"我在哪"的确定性下降一级、返回路径变长；而第 4 级页面通常说明上一级没承担好"目录"职责，或该功能本应换一种交互形态。

## 规则

1. **层级怎么数**：MainView 主页 = 第 1 级；主页按钮进入的功能页（RecipeHomeView、手动操作等）= 第 2 级；功能页内的子页面（如配方详情编辑）= 第 3 级。到此为止。
2. **按最长前进链数，不按 Journal 记录数**：层级 = 从主页沿前进方向的最长跳转链长度；GoBack/GoForward 不产生新层级。
3. **第 4 级是红线**：任何新页面设计不应产生第 4 级。
4. **超深需求的扁平化去向**：
   - 展示/编辑当前对象的细节 → `LayoutPageControl.RightContent` 属性面板（master-detail）
   - 页内多块内容 → Tab / 分段切换，不跳转
   - 临时性、确认性、短编辑操作 → Dialog 弹窗
   - 当前页附属的子操作 → `ToolBoxContent` 底部工具栏
   - 如果它其实是独立业务领域 → 提升到主页直接进入，而不是藏在第 3 级下面
5. **Dialog 不计层级**：弹窗不进 MainRegion 的 Journal，是页内临时交互，不是导航。
6. **执行方式：约定 + review 守**：导航深度是设计问题，代码里没有可靠的"级数"可判（同名 View 可复用在不同深度），不做运行时拦截。

## Considered Options

- **运行时硬限制**（`NavigationService.NavigateToAsync` 按 Journal 深度拦截）：弃用——"级数"在代码里不可靠，同名 View 复用在不同深度很正常，硬拦截会误伤合法流程。
- **只做口头约定、不落文档**：弃用——没有落点，新人和 agent 无从查起，review 时没有依据。
- **文档约定 + review 守（选定）**：与 ADR-0002 同款执行方式（约定不设编译器硬墙）；将来若有需要，可在 NavigationService 按 Journal 深度打 warning 日志留痕，仍不拦截。

## Consequences

- review 页面类 PR 时多一条检查项：这条跳转链有多长？
- 框架的 `IRegionNavigationJournal` 本身不限制深度，本约定不依赖也不修改其行为。
- 若某业务确实需要更深，正确动作是重开本 ADR 讨论，而不是绕过扁平化手段硬跳。
